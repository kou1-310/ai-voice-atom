# ユースケース一覧

> **この文書の位置づけ**: 利用場面（ユースケース）の一覧と詳細です。実際の操作手順は [manual.md](manual.md) を参照してください。
> ほかの文書は [docs/README.md](README.md) から探せます。

## 1. 前提

本一覧は、AtomS3-Lite と Atomic Echo Base を使う音声対話デバイスの初期検討用ユースケースである。

本システムは、ホスト連携のモード（web / voice / relay）と、ホスト不要のモード（recorder / parrot / timer）を持つ。
Web UI はホストが配信する（2026-09-23 更新）。

優先度は以下の 3 段階とする。

- Must: 初期開発で必須
- Should: 早い段階で欲しい
- Could: 拡張候補

## 3. 主要ユースケース詳細

### UC-03 モード切替

- 目的: デバイス単体で利用モードを切り替えられるようにする
- 事前条件: デバイス起動済み
- トリガー: ボタン長押し（1.2秒・全モード共通）
- 基本フロー:
  1. デバイスが現在モードを確認する
  2. 次のモードへ切り替える（`web → voice → relay → recorder → parrot → timer → web` の順に巡回）し、NVS に保存する
  3. LED と音声案内（未生成ならチャイム）で新しいモードを通知する（web=青 / voice=緑 / relay=シアン / recorder=白 / parrot=黄 / timer=紫）
- 代替フロー:
  1. 処理中はモード切替を保留または拒否する

### UC-05 Web UI アクセス

- 目的: ブラウザからデバイス（とペルソナの会話）を操作可能にする
- 事前条件: ホストが起動済みであること。実機を使う操作では実機が relay モードで接続済みであること
- トリガー: ブラウザでホストの `http://<ホスト>:8000/frontend/` にアクセスする
- 基本フロー:
  1. ホストが静的アセット（`frontend/`）を返す
  2. ブラウザが操作画面を表示し、ペルソナ一覧と接続中の実機を取得する
  3. 利用者が実行モード（画面でデモ／実機で会話／実機に話しかける）を選んで操作する
- 代替フロー:
  1. 実機が接続されていない場合は、接続中の実機が無い旨と relay モードへの切替を案内する

### UC-06 Web UI 操作

- 目的: 音声入力を使わずにブラウザから操作する
- 事前条件: Web UI が表示されている
- 基本フロー:
  1. 利用者がテキストを入力する
  2. フロントエンドがホスト API を呼び出す
  3. ホストが LLM・TTS を処理し、必要なら実機へ再生を指示する（WebSocket の `play`）
  4. 応答結果と再生状態をブラウザへ返す

### UC-07 テキスト問い合わせ送信

- 目的: 最小構成で LLM 接続の成立を確認する
- 事前条件: Wi-Fi 接続済み、バックエンド疎通可能
- トリガー: ボタン押下または Web UI 操作
- 基本フロー:
  1. デバイスが問い合わせを生成する
  2. バックエンドへリクエストを送信する
  3. 応答待機状態を表示する
- 代替フロー:
  1. 通信失敗時はエラー表示に切り替える

### UC-08 LLM 応答取得

- 目的: OpenAI API 互換の応答を取得する
- 事前条件: API 設定が有効
- 基本フロー:
  1. バックエンドが LLM API に問い合わせる
  2. 応答テキストを整形する
  3. デバイスまたは TTS サービスへ渡す
- 代替フロー:
  1. API エラー時は再試行または失敗応答を返す

### UC-09 TTS 音声取得

- 目的: 応答テキストを再生可能な音声へ変換する
- 事前条件: TTS サービスが利用可能
- 基本フロー:
  1. 応答テキストを Irodori-TTS に送る
  2. wav 音声を生成する
  3. デバイスへ返却する
- 補足:
  1. 初期フェーズは wav 固定を推奨する
  2. mp4 は後続対応とする
  3. Irodori-TTS の実体配置は third_party/irodori-tts の submodule を前提とする

### UC-10 スピーカー再生

- 目的: 生成音声を Echo Base スピーカーから出力する
- 事前条件: Echo Base 初期化済み
- 基本フロー:
  1. デバイスが音声データを受信する
  2. 再生バッファへ投入する
  3. スピーカー再生を開始する
  4. 再生完了後に待機状態へ戻る
- 代替フロー:
  1. 不正な形式の音声は再生せずエラー扱いにする

### UC-14 音声入力録音

- 目的: 音声対話への拡張基盤を作る
- 事前条件: マイク入力が利用可能
- トリガー: voice モードでボタンをクリック（将来はウェイクワード）
- 基本フロー:
  1. クリックで録音を開始する
  2. もう一度クリックで録音停止し音声データを送信する
  3. STT 処理へ渡す

### UC-15 STT 変換

- 目的: 録音音声をテキストへ変換し対話に利用する
- 事前条件: 音声データが取得済みであること
- 基本フロー:
  1. デバイスが WebSocket ストリームで音声チャンクを送信する
  2. バックエンドが Moonshine に音声を渡す
  2. Moonshine が逐次または完了後の文字起こしを返す
  3. 文字起こし結果を LLM 入力に整形する
- 補足:
  1. Moonshine は低遅延なライブ音声処理向けエンジンとして採用する

### UC-18 WebSocket 音声ストリーム

- 目的: 音声対話のレイテンシを下げる
- 事前条件: 音声対話モードであり、ホストへの WebSocket 接続が確立していること
- 基本フロー:
  1. デバイスがセッション開始イベントを送る
  2. 音声チャンクを順次送信する
  3. ホストが partial STT を返す
  4. 録音終了後に最終文字起こしと応答生成へ進む
- 代替フロー:
  1. 接続断時は録音停止とエラー通知に切り替える

### UC-17 Web 状態監視

- 目的: ブラウザからデバイス状態を把握できるようにする
- 事前条件: Web UI 接続中であること
- 基本フロー:
  1. フロントエンドが状態取得 API を呼び出す
  2. デバイスが現在モード、再生状態、接続状態を返す
  3. UI が状態表示を更新する

### UC-22 デバイス別ペルソナ

- 目的: 複数の AtomS3 を別個の AI（別ペルソナ・別声色）として動かす
- 事前条件: `device_profiles.json` に `device_id → {system_prompt, ref_wav, display_name}` を定義
- 基本フロー:
  1. 各機が固有の `device_id` を `/api/chat/audio` や WS `session.start` に乗せる
  2. ホストが `device_id` でプロファイルを引き、system プロンプトと TTS の声色を出し分ける
  3. 会話履歴は `device_id::session_id` の複合キーで分離する
- 代替フロー:
  1. 未登録 `device_id` はグローバル設定（`llm_system_prompt` / `tts_ref_wav`）へフォールバックする

### UC-24 実機リレー会話

- 目的: 2 体のペルソナを、ホスト統括で交互に会話させて実機で再生する
- 事前条件: 出力先の実機が relay モードで `/ws/audio` に `register` 済み、`device_profiles.json` 設定済み
- トリガー: フロント（実機で会話）／`POST /api/conversation/start`（device_a/device_b/opening_text/max_turns/output_device_a/output_device_b）
- 基本フロー:
  1. ホストが話者のターンのテキストを LLM で生成する
  2. 話者ペルソナの出力先の実機へ WS で `play`（`persona` 付き）を push する
  3. 実機が `/api/chat/say`（`persona_id`）でそのペルソナの声色の音声を取得・再生し、`played` を返す
  4. ホストが ack を待って相手のペルソナへ次のターンを回す（`max_turns` まで）
- 代替フロー:
  1. 出力先を両方同じ実機にすると、1 台が 2 体の声色を切り替えて再生する
  2. ack タイムアウト（`RELAY_ACK_TIMEOUT`、既定 180s）で会話を中断し状態を戻す
  3. `/api/conversation/stop` で途中停止する

### UC-25 実機への話しかけ

- 目的: 実機 1 台でも、Web UI から実機のキャラクターと会話できるようにする
- 事前条件: 出力先の実機が relay モードで登録済み
- トリガー: フロント（実機に話しかける）／`POST /api/conversation/chat`（persona_id/text/output_device/session_id）
- 基本フロー:
  1. ホストが `persona_id` のペルソナで返事を生成する（履歴は `persona_id::session_id`）
  2. 出力先の実機へ `play` を push し、`played` を待つ
  3. 返事のテキストをフロントへ返し、会話ログに表示する
- 代替フロー:
  1. リレー会話の実行中は受け付けない（400）。実機未接続は 409、LLM 失敗・ack タイムアウトは 503

### UC-26 単体録音再生

- 目的: ホストや Wi-Fi が無い場所でも AtomS3 単体で遊べるようにする
- 事前条件: recorder モード（LED 白）
- 基本フロー:
  1. クリックで録音を開始し（赤点滅）、もう一度クリックで停止してフラッシュ（LittleFS）に保存する
  2. ダブルクリックで最後の録音を再生する（再生中のクリックで停止）
- 代替フロー:
  1. 最大 30 秒または空き容量に達したら自動で停止・保存する
  2. 録音が無いときは「まだ録音がありませんわ。」と案内する（案内未生成ならエラー音）

### UC-27 オウム返し

- 目的: ボタン操作なしで、話しかけるだけで遊べるようにする（子どもでも遊べる）
- 事前条件: parrot モード（LED 黄）
- 基本フロー:
  1. デバイスがマイクで聞き続け、雑音レベルを学習する
  2. 音量がしきい値を超えたら、直前 0.2 秒を含めて録音を始める（LED 点滅）
  3. 0.7 秒静かになったら録音を止め、選んだ声（高い／ふつう／低い）で言い返す
  4. 0.3 秒待ってから聞き取りに戻る
- 代替フロー:
  1. 有音が 0.3 秒未満なら雑音として捨てる。10 秒に達したら自動で止めて言い返す
  2. クリックで声の種類を切り替える（声で案内し、記憶する）

### UC-28 声で知らせるタイマー

- 目的: ホスト無しで、キャラクターの声で時間を知らせるキッチンタイマー・ポモドーロとして使う
- 事前条件: timer モード（LED 紫）
- 基本フロー:
  1. ダブルクリックで時間（1/3/5/10/25 分）を選ぶ（声で案内し、記憶する）
  2. クリックでスタート。LED が残り時間で緑 → 黄 → 赤と変わる
  3. 2 分以上なら残り 1 分で「残り1分ですわ。」と知らせる
  4. 時間になると「時間ですわ！」を繰り返し、クリックで止める
- 代替フロー:
  1. 動作中のクリックで中止する。別モードへ切り替えると中止する
  2. 止めなくても約 30 秒でアラームを終える
